# Task

Implement the second half of milestone M1 of forever-gear-planner: the static page in `site/` (index.html,
style.css, the DOM code in `site/app/`), on top of the generated beta data and the `site/lib/` modules that the
first M1 session built and tested. The result is the "first usable page": a stranger opens `site/index.html` from
disk, builds a roster, and gets a ranked crafted-gear path for levels 1–60 per roster entry, with source badges and
prices from their own Auctionator file.

The maintainer runs the seven-step acceptance check of `docs/roadmap.md` §M1 on the result and then publishes the
page during the WoW: Forever beta (P1, target 2026-10-27), so the page must work from `file://` with networking off
and must not depend on anything outside `site/`.

# Constraints

- Static page: classic scripts in a fixed order (`data/forever/*.js`, `lib/*.js`, `app/*.js`), relative paths, no
  `type="module"`, no `fetch`, no `import`, no root-relative URLs, no external requests of any kind, no icons.
  Everything must work when `site/index.html` is opened from `file://` with networking disabled.
- Privacy: nothing personal in the repo. `tools/privacy-check.sh` runs on every commit through the hook; a failing
  check is a stop. Do not open `../../web/forever-gear/`, `../../tools/`, `../../notes/` or anything under
  `../../` other than `../.fgp-port/ui/`.
- Edit files in place with targeted replacements. Do not draft a file or section in a scratch file and reassemble
  it, and do not rewrite a whole file; the output tokens spent on edits are best minimized whenever that does not
  change the end result.
- Keep `site/lib/` stable: the first session's tests pin their behaviour. Additive changes with a test are fine;
  changed signatures or stored shapes need the orchestrator's go (schema 1 is what the export format promises).
- The page must stay within the size budget tested by `tests/js/smoke-data.test.js`: `site/` ≤ 4 MB in total.
- Commit in coherent steps on `main` with the attribution line Claude Code gives you; do not add a remote or push.
