# Task

Implement milestone M2 of forever-gear-planner: the crafting Queue view per profession across the roster with an
"Auction House" pseudo-crafter, the shopping list with owned mats and the two totals ("Value of mats used" and
"To buy"), per-item crafter choice, the specialisation select for Blacksmithing, Leatherworking and Engineering,
the crafter-pace lines, and the `tools/prices-default.js` generator for a default price list (tool and tests only;
no list is shipped before the live game, U3). Release it as v0.2.0.

This is for players who level several characters on one account and craft for each other: the Gear view tells
each character what to wear, the Queue tells each crafter what to make, in what order, and what to buy for it.
Until M2 the public planner lacks the one feature that makes a multi-character roster worth entering.

# Known problems / dead ends

- `path()` always prefers a roster crafter over the AH; there is no "prefer AH" switch and the page has none
  (decided in M1). The per-item crafter choice in M2 is an override of `routes[itemId].via` for one item, stored
  on the item state (`via`), and it must survive a re-render and an export.
- Owned mats never change scores or the path (pricing §5.2): they change the shopping list's "To buy" total and
  the per-row "need" only. Do not feed `owned` into `costOf`.
- The prototype keyed learned recipes by item ID; the public state keys them by crafter entry ID and recipe spell
  ID (`recipes["<entryId>:<spell>"]`). A recipe with several patterns or spells (D13 R7) is one row per spell.
- The oracle test (`tests/js/oracle.test.js`, 56/68 core, 82.4 %, gate 80 %) runs with `allLearned` and no spec
  set, so the spec gate must leave it unchanged. Any rank change that moves it needs the orchestrator's go first.
- There is no Favor view and no enchant or consumable data (M3, M4): the queue shows gear recipes only, and the
  "kits and consumables" section of ui.md §5 is left out with a one-line note in the view.
- `tools/prices-default.js` produces `site/data/forever/prices-default.js`, but that file is **not committed** in
  M2 (U3): the tool runs on a fixture into a scratch directory in its test, `.gitignore` keeps the real output out,
  and the page handles both "no default list" and "default list present" (the pricer already accepts `defaultSet`).

  change the end result.

  that the Queue also sets.
- Performance: a roster of eight entries with two professions each must render the Queue in well under a second
  on a laptop; compute paths once per render and reuse them across the Gear and Queue views.

# Definition of done

1. Queue view (`site/app/queue.js`, registered as view `queue`, tab, keyboard shortcut, `prefs.view` accepts it):
   crafter buttons for every entry with a crafting profession, then "Auction House", then "All"; skill inputs per
   profession (estimated skill shown as `~`); "Core only", "Show hidden", "within N levels" (default 5).
2. To craft table per ui.md §5: learned checkbox per crafter and recipe spell ID, skill with `!`/`~!` flags
   (D26), item with slot, "for whom at which level" buttons that mark the piece in bags for that entry (status
   `have`, `via` the crafter), quantity across entries, source badge, cost each and total; BoP pieces appear only
   under their own crafter; the Auction House list shows BoE pieces routed to the AH with price, source and date
   and a "mark in bags" button; "All" shows everything grouped by crafter.
3. Crafter pace: per profession, the next three breakpoints "entry X reaches level N → needs skill S" from the
   queue rows and `roles.pace`.
4. Shopping list for the selected crafter (and for All): mats aggregated through intermediates (`craftCost`
   depth), unit price with its source and age, "Have" column editing `prices.owned`, `need = max(0, required −
   owned)`, the totals "Value of mats used" and "To buy", mats the roster can gather marked with the entry, and a
   count of mats without a price.
5. Per-item crafter choice: on a Gear or Queue row with more than one possible route, a select of the crafters
   (and the AH when the piece is BoE and the AH switch is on) that sets `items[...].via`; `path` honours it
   through `opts` (additive), the choice survives re-render, export and import, and is cleared when that entry is
   removed (state.js already drops `via` pointing at a removed entry).
6. Specialisation select in the entry form for Blacksmithing, Leatherworking and Engineering, shown once level
   ≥ 40 or the entered skill ≥ 200, stored in `professions[].spec`; with a spec set, a spec-gated recipe is
   craftable only by a crafter with that spec, and the badge reads "needs <spec>" otherwise; with no spec set
   the recipe stays craftable with the badge (D28). The oracle result is unchanged.
7. `tools/prices-default.js <Auctionator.lua> --realm <key> --build <build> --date <YYYY-MM-DD>` writes
   `site/data/forever/prices-default.js` (window.FGP_DATA.pricesDefault: dataset, build, scan date, realm count,
   rows) and refuses a build mismatch; test on the synthetic fixtures into a scratch dir; the real output is
   gitignored; `site/lib/pricing.js` precedence override > vendor > imported > default > craft is tested with a
   default set present.
8. Tests: `tests/js/queue.test.js` (rows, quantities, within-N, learned, pace, AH list, All), `shopping` with
   owned, the crafter choice and the spec gate in `rank.test.js`, state normalize for the new fields with a
   v0.1.x export fixture, the acceptance flow in `site-app.test.js`; `tools/check.sh` green; oracle unchanged.
9. Acceptance in a browser from `file://`, networking off (do what you can headless, list the rest): example
   roster → Queue → Mage shows Tailoring and Enchanting pieces for the roster with quantities; Warrior shows
   Blacksmithing pieces incl. the Rogue's weapons; Auction House lists the Rogue's BoE leather with "no price";
   importing the synthetic Auctionator file fills prices and the shopping list; entering owned mats lowers "To
   buy" but not "Value of mats used"; a crafter choice on one piece moves it between crafters; a level-45
   Blacksmith with Armorsmith set hides Weaponsmith recipes from its queue; keyboard only through all of it;
   export → reset → import restores the queue state.
10. README "Use it" and the About view mention the Queue; `CHANGELOG.md` `[0.2.0]`; `APP_VERSION` `0.2.0`;
    orchestrator's go; tag pushed; Pages deploy green; completion message sent.
